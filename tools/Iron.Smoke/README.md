# Iron.Smoke

Runs against a live stack and exits 0 when every step passes. Each step names the requirement criteria or the decisions it proves (`report.StepAsync("login", ["TF-011 AC1"], ...)`, ADR-0044), which its report line and the JSON report show and `make trace` reads. Steps, in order: `control-token`, `tenant` (provision or reuse `smoke`; a tenant it provisions hands its administrator's invitation over once, in the report, ADR-0046), `health`, `smoke-token`, `token-call`, `administrator` (a password known from an earlier run at `tenants/<tenant>/smoke` in the store; otherwise the invitation the tenant step was given, or one an update re-issues while the administrator is still Invited, accepted with a generated password kept there first), `recovery` (S3 T2, ADR-0046: the operator's recovery link, asked of the control plane with the run's reason, issued in the unit by the fleet and handed over through the store; the report gives it once and not again, and the job's output holds no link; it sets a new password once, which the store keeps; a second use answers 404; the earlier password is refused; both audit trails show the reason; so a run that started without the password ends with it), `login`, `cookie-call`, `denials` (anonymous 401, another tenant's token 401, a `service-default` account creating a tenant 403), `logout`, `trace` (the cookie call's correlation id found in Tempo), then S2's `scoped-role`, `plan-change` and `kill-switch`, each restoring what it changed; `scoped-role` deactivates the reader it made, and the readers earlier runs left active, whatever the result.

Environment (laptop defaults in brackets): `SMOKE_CONTROL_URL` [http://localhost:5200], `SMOKE_OPERATOR_CLIENT_ID` [operator], `SMOKE_OPERATOR_SECRET` (required), `SMOKE_READER_CLIENT_ID` [smoke-reader], `SMOKE_READER_SECRET` (optional; without it the 403 case is skipped), `SMOKE_TENANT` [smoke], `SMOKE_BASE_DOMAIN` [localhost], `SMOKE_INGRESS_URL` [http://localhost], `SMOKE_STORE_ADDRESS` [http://localhost:8200], `SMOKE_STORE_TOKEN` (required), `SMOKE_TEMPO_URL` [http://localhost:3200; `skip` skips the trace step], `SMOKE_REPORT` [smoke-report.json; `make smoke` passes `artifacts/test-results/smoke/smoke-report.json`], `SMOKE_PROVISION_TIMEOUT_SECONDS` [900].

The cookie is carried by hand (not a cookie container), so the Secure flag does not stop the test on plain http; TLS errors are ignored for the laptop's self-signed certificate.

The `single-sign-on` step (ADR-0048) needs the test provider (`make test-provider`, which `make smoke` runs first; the integration stage starts it too). It tests the connection of the tenant's "Smoke test provider" (issuer `smoke-<tenant>` at `http://idp.localhost`), connects it once and sets a new client secret on every run, then signs a new person of the run in through it as a browser would: the unit's authorization address, the provider's login page with the run's claims (reached through the ingress with `Host: idp.localhost`), and the provider's way back posted to `/auth/sso/callback`. The person, created at that first sign-in, is deactivated at the end whatever the result.

The `audit-trail` step (S3 T6, ADR-0050) comes last and reads only. As the administrator it finds this run's `identity.session_ended` event by the reason the `end-session` step gave ("Smoke run <run>: ..."), searches the trail by that person's record, and checks every event of the person in time order (created, session ended, deactivated, TF-064 AC1); it waits, at most a minute, for the unit's worker to seal each into the chain, under the chain's head; then it exports the same search to CSV and checks the file's title, filters and one row per event. A unit made before T6 seals nothing until `make update-unit`.

The `health` step waits, at most 90 seconds, for the API's own readiness answer through the ingress, a 200 with its JSON status: just after provisioning, the ingress may not route to the tenant's API yet, and the tenant's shell answers every path with its page and 200 (M4, after the release run 39541982335 failed on it).

Two steps of S3 T9b (ADR-0054). `tls` (TF-074 AC3) writes ClientHellos byte by byte to the ingress's port 443, so the smoke's own TLS library cannot refuse first: TLS 1.0 must be refused with a protocol version alert, TLS 1.2 offering only old suites (CBC with RSA key exchange) with a handshake failure, and TLS 1.2 with modern suites must get a server hello. `key-rotation` (TF-075 AC1, TF-074 AC2, AC4) stores a key check of the run (a value the tenant keeps encrypted and finds by its exact value), has the operator rotate the tenant's index key with a fresh token and the run's reason, waits, at most three minutes, until the unit has made every hash again and the fleet has retired the old version, checks that the unit reads only the new version, and finds the check by its exact value and not by a part of it. A rotation an earlier run left open is waited for first.
