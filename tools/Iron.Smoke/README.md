# Iron.Smoke

Runs against a live stack and exits 0 when every step passes. Each step names the requirement criteria or the decisions it proves (`report.StepAsync("login", ["TF-011 AC1"], ...)`, ADR-0044), which its report line and the JSON report show and `make trace` reads. Steps, in order: `control-token`, `tenant` (provision or reuse `smoke`), `health`, `smoke-token`, `token-call`, `administrator` (a password known from an earlier run at `tenants/<tenant>/smoke` in the store; otherwise keeps a generated one there, then accepts the invitation once; a lost answer is tolerated), `recovery` (S3 T2, ADR-0046: the operator's recovery link, asked of the control plane with the run's reason and issued in the unit by the fleet, sets a new password once, which the store keeps; a second use answers 404; the earlier password is refused; both audit trails show the reason; so a run that started without the password ends with it), `login`, `cookie-call`, `denials` (anonymous 401, another tenant's token 401, a `service-default` account creating a tenant 403), `logout`, `trace` (the cookie call's correlation id found in Tempo), then S2's `scoped-role`, `plan-change` and `kill-switch`, each restoring what it changed; `scoped-role` deactivates the reader it made, and the readers earlier runs left active, whatever the result.

Environment (laptop defaults in brackets): `SMOKE_CONTROL_URL` [http://localhost:5200], `SMOKE_OPERATOR_CLIENT_ID` [operator], `SMOKE_OPERATOR_SECRET` (required), `SMOKE_READER_CLIENT_ID` [smoke-reader], `SMOKE_READER_SECRET` (optional; without it the 403 case is skipped), `SMOKE_TENANT` [smoke], `SMOKE_BASE_DOMAIN` [localhost], `SMOKE_INGRESS_URL` [http://localhost], `SMOKE_STORE_ADDRESS` [http://localhost:8200], `SMOKE_STORE_TOKEN` (required), `SMOKE_TEMPO_URL` [http://localhost:3200; `skip` skips the trace step], `SMOKE_REPORT` [smoke-report.json; `make smoke` passes `artifacts/test-results/smoke/smoke-report.json`], `SMOKE_PROVISION_TIMEOUT_SECONDS` [900].

The cookie is carried by hand (not a cookie container), so the Secure flag does not stop the test on plain http; TLS errors are ignored for the laptop's self-signed certificate.

The `health` step waits, at most 90 seconds, for the API's own readiness answer through the ingress, a 200 with its JSON status: just after provisioning, the ingress may not route to the tenant's API yet, and the tenant's shell answers every path with its page and 200 (M4, after the release run 39541982335 failed on it).
