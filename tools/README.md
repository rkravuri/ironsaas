# Tools

| Tool | What it does |
|---|---|
| `Iron.Smoke` | The smoke test: drives the running stack from the outside through the control plane and the ingress, provisions or reuses the `smoke` tenant, signs in with a token and with a cookie, proves the denials, finds the request's trace in Tempo by its correlation id, then a scoped role, a plan change and a kill switch. Each step names the criteria or decisions it proves (ADR-0044). `make smoke` on the laptop writes `artifacts/test-results/smoke/smoke-report.json`; the integration stage in the pipeline (T18) uploads its report. |
| `Iron.ProcessMaps` | The process maps' check (ADR-0045): every process reference pack in `docs/prd` has its BPMN maps in the folder named after it, and each map is valid against OMG's BPMN 2.0 schema (in `schema/`, unchanged, `docs/licences.md`), with every reference naming an element of the file, every flow node in one lane, every element on the diagram and every task named by its step identifier. `make prd-check` runs it after `prd_check.py`; its tests (`tests/Iron.ProcessMaps.Tests`) run with `make test`. |
| `prd_check.py` | The requirements check (ADR-0041): every identifier once across the documents in `docs/prd` and their CSVs, every identifier of the archived Functional Foundation PRD in the map, criteria in the Given, When, Then form with an error case, the product PRDs' sections, and each CSV equal to its markdown; a retired requirement names its successors and nothing depends on it; a process reference pack's section 2 maps every live requirement of its module to a PCF element and a map step (PM-001 AC2). `make prd-check` runs its tests (`prd_check_test.py`) and then the check, in CI too; `make prd-csv` writes the CSVs from the markdown. |
| `trace.py` | The traceability matrix (TF-218, ADR-0044): every test of every kind with the requirement criteria and decisions it names, read from the sources, joined to its result from the last run's files under `artifacts/test-results`, into `artifacts/trace/matrix.md` and `matrix.json`. It fails on an identifier no document holds, a done slice's criterion without a test or an approved exception (`docs/trace/exceptions.md`), and a result it cannot place. `make trace` runs its tests (`trace_test.py`) and then the trace; CI publishes the matrix. |
| `unittest_junit.py` | Runs a tool's Python tests as `unittest` does and, with `--junit <file>`, writes their results as JUnit for the matrix. |

The scaffolding tool that creates a module or an entity from templates (TF-190) arrives after slice S1; the S1 modules are the templates it will copy.

Tools are console programs with `<IronLayer>Tool</IronLayer>` (ADR-0029). They may reference the libraries they need and are outside the module boundary rules; they are not part of any image. The requirements check is a Python script with the standard library only, outside the .NET build; the maps' check is .NET because Python's standard library cannot validate against an XML schema (ADR-0045).
