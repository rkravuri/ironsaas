# ADR-0025: The design foundation

Date: 2026-10-18
Status: Accepted

## Context

ADR-0024 decided the design language and left its materials to the first task of S2: the tokens, the type families, the colour rules and the gallery that the accessibility scan reads (items 4, 5, 7 and 8). This record holds the choices D1 made while building them. The shell's content security policy allows scripts, styles and fonts from its own origin only, which rules out inline scripts and font services.

## Decision

1. **Type.** The reading family is Source Sans 3 (variable; Adobe; SIL Open Font License 1.1): humanist, good numerals, tabular figures for the grid. The display family is Fraunces (variable; Undercase Type; SIL Open Font License 1.1): a soft serif with character, used only through `Title` with `variant="display"` at orders 1 and 2 (32 and 24 pixels); the theme ignores the variant below that, so the brief's "not under 24 px" holds by construction. Code uses the system monospace stack. Both families ship from the `@fontsource-variable` packages at exact versions (ADR-0003), bundled by Vite and served from the shell's own origin, which the policy allows and which leaks no visit to a font service. Six sizes: 12, 14, 16, 20, 24 and 32 pixels with line heights 16, 20, 24, 28, 32 and 40.
2. **Tokens as the single source.** `shell/src/design/tokens.ts` holds ink and paper, the neutral scales, the accents, the type scale, spacing, radii, motion and the density row heights, as one typed object. The theme reads it; Mantine's CSS variables resolver emits the `--iron-*` variables from it on `:root` and under both scheme attributes; no stylesheet repeats a value.
3. **Colour from one generator.** Ink and paper are four fixed OKLCH values; every other colour is derived. An accent is one hue and one chroma, expanded into ten shades on one fixed lightness table (`colour.ts`), so the accents are one family and satisfy the same contrast pairs. Mantine derives its text, filled, light and outline variants from fixed shade indices; `primaryShade` is 6 in both schemes, because shade 8 on the dark paper would fail 3:1 for the focus ring and filled buttons. The neutrals are two scales, gray for the light scheme and dark for the dark scheme, placed so that dimmed text keeps 4.5:1 and borders keep 3:1 (WCAG 1.4.11), which makes borders stronger than Mantine's defaults. The documented pairs are tested against the variables Mantine actually emits, not against the tuples; a Mantine upgrade that moves a derivation fails the test. A tenant colour (TF-173) goes through the same generator and the same check.
4. **Names, not hues.** Product code names `primary`, `identity`, `console`, `success`, `warning`, `danger`, `info`, `dimmed` and the `--iron-*` variables. Mantine's `error`, `success` and `placeholder` variables point at those colours. Status is never colour alone.
5. **The colour rule is the boundary** (ADR-0021 item 6, extended). `no-restricted-syntax` in `eslint.config.js` refuses a hex, `rgb()`, `hsl()`, one of the 148 CSS colour keywords or a Mantine palette name (`red`, `gray.6`, `dark`) wherever JSX styles something: `style`, `styles`, `vars` and `gradient` objects at any depth, the colour props `c`, `bg`, `bd` and `color`, and `fill` and `stroke`. It covers all of `src/` except `src/design/`, where values are defined, and the grid theme, which maps them into AG Grid. `src/lint.test.ts` proves it. A colour in a plain object later passed as a style is for review, not lint.
6. **Stylesheets get the same rule through a test.** The build has no CSS linter; the lint test reads every `.css` file under `src/` outside `src/design/` and asks the colour rule about each declaration value, so "raw colour" is defined once. `@eslint/css` with a custom rule is the step up when CSS modules exist in number.
7. **Density and motion.** Density (`comfortable`, `compact`) is a per-viewer convenience kept in the browser's storage and exposed as `data-density` on the root; the grid reads it for its row height. Motion is 150 ms for a change under the pointer and 250 ms for something that arrives or leaves; `prefers-reduced-motion` turns every transition into a cut through one global rule, and Mantine's own `respectReducedMotion` is on.
8. **No flash on a dark reload.** `shell/public/scheme.js`, a plain external script that `index.html` loads before anything else, sets the scheme attribute from the viewer's stored choice or the operating system before the first paint. Mantine's own `ColorSchemeScript` is inline, which the policy forbids.
9. **The gallery is a development build.** The `/gallery` route exists only when `import.meta.env.DEV`. `npm run gallery:build` runs `vite build --mode gallery` with `.env.gallery` setting `NODE_ENV=development`, the one way Vite 8 makes a development build from the command line, into `dist-gallery`, and `vite preview` serves it on a port of its own. The image runs `npm run build`, so the gallery never ships.
10. **The scan has its own Playwright config and its own job.** `playwright.a11y.config.ts` runs axe (`@axe-core/playwright` 4.13.0, Deque, MPL-2.0; an exact version two months old, as ADR-0003 prefers) with the WCAG 2.0 and 2.1 A and AA tags on the gallery in both schemes and both densities, with reduced motion emulated so it measures settled states, saves a screenshot of each, and fails on any violation; the main config ignores `e2e/a11y/`. `shell-accessibility` is the sixth job of `ci.yml`, independent of the others as ADR-0022 wants, and uploads the screenshots and the report on every run. A finding that cannot be fixed here goes in the spec's known-issue list with its rule id, the selector it is limited to and the upstream issue; nothing is excluded wholesale.

## Consequences

- The palette is reviewable in the gallery with its ratios; changing a lightness table changes every accent at once, and the test says whether that was allowed.
- A raw colour fails lint before review; a contrast or label mistake in a component fails CI in a job of about a minute that needs no Docker. The scan covers what the gallery shows, which is why the definition of done asks for the gallery entry.
- Borders are stronger than Mantine's defaults; the first load carries two font files of about 150 KB with `font-display: swap`; six CI jobs instead of ADR-0022's five.
- Options not taken: hand-written shade tuples (seventy values, no family, and TF-173 needs a generator anyway); `@mantine/colors-generator` (a dependency without lightness control); Inter or IBM Plex Sans for reading (fine, but colder than the brief asks); Google Fonts (the policy and privacy); a `VITE_GALLERY` flag (a production bundle that can carry the gallery); `@eslint/css` now (a dependency for zero files).
