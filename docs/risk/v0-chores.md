# Risk: V0, chores before slice V

The task touched these requirements (classes from `docs/trace/risk.md`):

| Requirement | Class | How it was touched |
|---|---|---|
| TF-013 Multi-factor authentication | critical (Identity and authentication) | The old column of authenticator secrets, sealed under the retired factor key, dropped; the code that moved them removed |
| TF-074 Encryption at rest and in transit | critical (Security) | Authenticator secrets live only under the tenant's data key now; the column of the retired key's ciphertext is gone |
| TF-076 Vulnerability and dependency management | critical (Security) | The x/net exception renewed with a corrected reason; the fleet's child processes without telemetry settings; every image by version and digest, kept current by Dependabot and held by a test |
| TF-210 Per-tenant deployment units | critical (Tenancy and control plane) | An update refuses, at its secrets step, a unit that still holds the retired factor key |

The change is classed **critical**.

**What could go wrong.** A unit whose authenticator secrets were never moved off the retired factor key could lose them for good: the drop would delete the only copy, and an update of this release would also write the unit secret without the key that opens them, so the people of that unit could no longer sign in with their authenticator app. A unit could start on the new image before its migration, or carry on half migrated. The refusal could be taken for a transient failure and retried, or read as one by an operator. Stripping the telemetry settings could strip something Docker needs, or miss a variable the binaries read, leaving the x/net exception's reason untrue. A digest could pin an image other than the one scanned, or Dependabot could stop seeing an image once it carried a digest, so fixes would stop arriving.

**What proves it does not.** On the laptop, before the drop, every database with Identity was read: acme, bravo, echo, golf and the control plane held no value in the old column, echo's 23 authenticator apps all on the new one; smoke had no factors table (last updated before T3); no unit, fleet or control secret held the retired key. The migration raises an error while any row holds a value: a database at T9b's migration with one unmoved secret makes `migrate` exit with a failure, keeps the column and the value, and does not record the migration; once the secret is moved, the same database migrates, the column is gone and the app's secret still opens to the same bytes (Identity `RetiredFactorColumnTests`, ADR-0054). The error is RAISE's own code, which Npgsql does not count as transient (the test checks it). An update of a unit whose unit secret, or whose fleet secret, still holds the retired key fails at the secrets step naming the key, with both secrets unchanged and no command run in the unit (Fleet `ProvisioningTests`, ADR-0054). A child process started by the fleet gets the fleet's environment less every `OTEL_*` and `DOCKER_CLI_OTEL_*` variable, the names the two binaries read among them, and keeps what Docker needs (Fleet `ProcessRunnerTests`, ADR-0055). Every image reference of the five Dockerfiles and the stack is pinned by version and digest and covered by a Dependabot entry, and a reference without either, or outside Dependabot, fails naming its file and line (Architecture `ImagePinRulesTests`, ADR-0055).

**Results.** make verify passed (its last step, `make trace`, after the gate's own test was made to read the register on its latest approval rather than on 2026-10-28): 1214 .NET test cases (921 methods), 397 Vitest, 152 scans, 92 Python; the gate with nothing failing; coverage 90.93% and 85.70% against floors of 90 and 85; the matrix with S1 to S3 done, 31 exceptions and none missing. On the laptop, on the branch's images: the control plane, acme, bravo, echo and smoke migrated without the column (smoke from T2 in one run), echo's 23 authenticator apps on the data key, and its administrator's kept authenticator key answering the smoke's second step; smoke 24 of 24 and browser tests 42 of 42 on echo; the five images through the gate with only the fleet's five findings excepted and nothing failing. Then `infra/compose/.control-factor-key` was deleted.

**What is left.** The four fleet findings that `docker:29.9.2-cli` fixes stay excepted until 2026-11-04, when it is two weeks old; the x/net finding in the Compose plugin until a Compose release with x/net v0.60.0 or later is two weeks old, at the latest 2027-01-28 (STATUS). The `# syntax=docker/dockerfile:1` line of each Dockerfile, the images the tests start through Testcontainers, the Makefile's scanner images and CI's are still pinned by tag only, until M6 on 2026-11-04; the stack and the tests run PostgreSQL's release candidate `19rc1` until its final release is two weeks old (STATUS). `infra/compose/.dev-factor-key`, the development host's retired factor key, read by nothing, was deleted at the review's word.
