# Risk: V-close, exceptions, documentation and the closing notes

The task touched these requirements (classes from `docs/trace/risk.md`):

| Requirement | Class | How it was touched |
|---|---|---|
| TF-218 Validation support for regulated tenants | critical (Regulated-industry controls) | `make trace` now reads V's plan, so V is a done slice in the matrix and every release's validation pack holds V's criteria with their tests; the trace tool gained a test |
| TF-241 Content visibility and visibility tags | critical (Visibility and access) | Held by the matrix as a done slice's requirement: its 8 criteria each have a test; no code changed |
| TF-244 Suites per tenant | critical (Tenancy and control plane) | Held by the matrix as a done slice's requirement: its 7 criteria each have a test; no code changed; the runbook gains the symptom of a tenant without a suite it expects |

The change is classed **critical**. Beside the requirements, it changed the build's tooling: an architecture test that every tracked shell script is executable, `init-env.sh`'s mode, two shell tests' globs with a lint rule, and documentation.

**What could go wrong.** The matrix could call V done while a criterion of TF-241 or TF-244 has no test, so a release's validation pack would claim more than the tests prove; or the change to which plans the matrix reads could drop a slice it held before, or read a file that is not a plan. The new architecture test could fail for a reason other than a script's mode (no git, a checkout without history) and block every change. The glob change could make the placement test or the stylesheet guard find nothing and pass empty. The documentation could send an operator down a wrong path: a tenant without the suite it bought, or a person who cannot see a record, diagnosed as something else; or the README could claim the eProcurement Suite is built when only its skeleton is.

**What proves it does not.** `make trace` passes with S1, S2, S3 and V as done slices: 323 criteria, 292 with a test, 31 approved exceptions, none missing; TF-241 and TF-244 have every criterion tested, so V adds no exception. The trace tool's new test proves a plan named by a letter is held to its criteria once its tasks are done, and its other tests that a plan with a task not done is not; S1 to S3 are read as before (the same 308 criteria and 31 exceptions as at S3-close). The architecture test reads `git ls-files --stage`, which works on CI's shallow checkout as on the laptop, and its fixture test proves the rule on made-up entries; it found `init-env.sh` at 100644 before the fix and passed after. The placement test still finds every manifest and checks it against the module list, the stylesheet guard still reads every stylesheet (its expectations are unchanged), and a module folder added after a cached run was found, with Vitest's debug log showing the file left out of its cache. The runbook's new symptoms were written from the code's own answers: the 404 `api.route.not_found` of a unit without the suite and the 403 `entitlements.module_disabled` past a plan's grace (V2's tests and laptop run), the 404 `data.record.not_found` of a record outside the reader's tags and the explanation's tag check (V1's). The README names the eProcurement Suite as declared, with Purchasing a skeleton and its masters PR0's. `make verify` passed on the branch on its first run, with coverage unchanged (90.54% and 85.54%); on main after the merge, `make verify`, `make smoke TENANT=echo`, `make e2e TENANT=echo` and the release run must pass before `v-done` is tagged.
